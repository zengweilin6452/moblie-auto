# Domain Docs

本项目采用 single-context 领域文档布局。

## 探索前读取

- 根目录 `GLOSSARY.md`：项目术语及其定义。
- `docs/adr/`：与当前任务相关的架构决策记录。

文件不存在时直接继续，不因缺失而要求补建。
在术语或决策实际明确后，再按需要创建相应文档。

## 目录约定

- `GLOSSARY.md`
- `docs/adr/<NNNN>-<decision-slug>.md`

不创建 GLOSSARY-MAP.md 或按模块拆分的领域文档体系。

## 使用项目术语

在任务标题、设计建议、测试名称和实现说明中，
使用 GLOSSARY.md 已定义的术语，避免替换成被明确排除的同义词。

需要的概念尚未收录时，先判断是否引入了不必要的新概念；
确有领域缺口时，记录为后续 domain-modeling 的输入。

## 明示决策冲突

方案与现有 ADR 冲突时，明确指出对应 ADR 和重新讨论的原因，
不得静默覆盖既有决策。
