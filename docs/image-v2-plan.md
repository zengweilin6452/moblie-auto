**文档状态**：已审查批准，按第八节决定实施（P4b 缓行）
**更新日期**：2026-10-24
**范围**：`src/mobile_auto/image.py` 模板匹配引擎及其相邻层（`assets.py` 模板缓存、`adapter.py` 调用路径），不改动 MobileAdapter 公共 API

## 一、v1 问题与实测证据

v1 为单尺度灰度模板匹配（`image.py:141` TM_CCOEFF_NORMED）+ 纯 Python 峰值提取与 NMS + RGB 均值差颜色验证。2026-10-24 在合成 1080×2340 截图 + 96×96 模板上分阶段计时：

| 阶段 | 耗时 | 占比 | 说明 |
| :--- | :--- | :--- | :--- |
| 截图 PNG 解码 | 37 ms | 13% | 每轮轮询重复发生 |
| 灰度 matchTemplate | 33 ms | 12% | OpenCV 本体，已接近免费 |
| `_local_peaks` 峰值提取 | **205 ms** | **74%** | 纯 Python 双层循环扫过 2.2M 分数格（`image.py:173`） |
| NMS / 颜色验证 | <1 ms | — | 峰值少时不是瓶颈 |
| **端到端** | **277 ms** | | `wait_for` 每 0.5 s 轮询一次，单轮匹配占掉一半以上预算 |

准确性两个结构性缺口（同日验证）：

1. **单尺度，跨分辨率完全失效**：截图放大 1.25× 后用原尺寸模板匹配，命中数 0。换 DPR 不同的设备或系统显示缩放变化即全部失败。
2. **颜色验证过弱**：RGB 均值绝对差（`image.py:222` COLOR_DIFF_MAX=16）会稀释局部颜色差异——灰底按钮上的小色点状态（红/绿）这类"形状相同、状态色不同"的负样本可能通过均值门。

另有一项小额固定开销：`adapter.py:94` 每轮轮询都重新执行 `TemplateStore.load`（读清单 + 元数据 + 图片 + sha256 + 解码，实测约 0.9 ms/次外加对象分配），同帧内多次查询（find_elements + 后续句柄重校验）也各来一遍。

## 二、Airtest 调研结论与可借鉴点

Airtest 的图像识别由策略链驱动（`airtest/core/settings.py` `CVSTRATEGY = ["mstpl", "tpl", "sift", "brisk"]`，前者命中即停），对我们有直接参考价值的是：

1. **多尺度匹配降本两件套**（`aircv/multiscale_template_matching.py`）：
   - 搜索图降采样到长边 ≤ 800px（`src_max=800`）再扫尺度，多尺度开销降一个数量级；
   - 模板按"相对屏幕长边占比"比例扫描（ratio ∈ [ratio_min, ratio_max]，步长 `scale_step`），带 3 s 预算早停。
2. **采集信息先验**（`MultiScaleTemplateMatchingPre`、`Template.match_in`）：
   - 录制时记录模板位置 `record_pos`（相对屏幕中心的归一化偏移）与采集分辨率 `resolution`；
   - 匹配时把两者换算到当前屏幕，预测搜索区域（边距 DEVIATION=150px）与缩放比例上下限（`_get_ratio_scope`），区域裁剪后再做小范围多尺度——既快又减少远处误匹配。
3. **颜色置信度**（`aircv/cal_confidence.py` `cal_rgb_confidence`）：两图裁到 [10,245] 后转 HSV，H/S/V 三通道各自做 TM_CCOEFF_NORMED 相关性，取**三通道最小值**。配合边框复制与角落置 0/255 的抗平坦退化技巧。比均值差判别力强得多，且天然区分色相状态差异。
4. **多目标查找**（`aircv/template_matching.py` `find_all_results`）：minMaxLoc 取最优 → 置信度校验 → 在分数矩阵上把已取出区域刷黑 → 循环，直到低于阈值或满 10 个。全 OpenCV 调用，无 Python 逐格循环。
5. **抗退化细节**：`src[0,0]=0; src[0,1]=255` 的角落技巧防止平坦窗口上 TM_CCOEFF_NORMED 分数发散；特征点路径对 <5px 或缩放超 5× 的结果直接判非法。

不适合照搬的部分：特征点匹配（SIFT/BRISK，CVSTRATEGY 后段）面向大图/游戏画面，我们的模板多为 20–100px 小图标，特征点稀少且不稳定，首版 PRD 也已明确排除；`cocos_min_strategy` 分辨率猜测面向游戏引擎，原生 Android 有确定的 DPI 映射，用线性比例推导即可。

## 三、目标与非目标

**目标**

1. 同分辨率单次匹配端到端从 ~277ms 降到 **≤100ms**（1080×2340 量级截图）。
2. "形状相同、状态色不同"的负样本可靠拒绝（HSV 门），同时不引入新的误拒。
3. 跨分辨率（不同 DPR / 显示缩放的设备）在有采集分辨率元数据时自动适配，无需为每台设备重做模板。
4. MobileAdapter 15 方法契约、`Target` 字段、`MatchResult` 结构、错误类型全部不变。

**非目标**

- OCR、旋转搜索、任意尺度搜索、特征点匹配、视觉大模型（维持 PRD 排除项）。
- 透明蒙版模板：维持首版"不透明 PNG"决定（开放问题 3 保留复议入口）。
- 修改 `confidence` 默认值与语义（灰度相关性分数仍为返回的 confidence）。

## 四、方案设计

分四项，P1/P2 纯提速零行为变化，P3/P4 提准确率（P4 改变"同分辨率才可用"的首版边界，见开放问题 1）。

### P1 峰值提取与 NMS 向量化（速度，零行为变化）

`_local_peaks` 改为全 numpy/OpenCV：

```
local_max = (scores == cv2.dilate(scores, np.ones((3,3))))   # 8 邻域极大,含自身
mask = (scores >= threshold) & local_max
peaks = np.argwhere(mask)                                     # (y,x) 升序,天然稳定序
```

平台区语义与 v1 一致（平台内所有格子都视为峰值，交给 NMS 去重）；`MAX_PEAKS` 上限检查改为先数 `mask.sum()` 再物化，超限仍报 MatchOverflow。NMS 保持贪心 + IoU 抑制，但对"已保留集合"的 IoU 判定改为 numpy 批量计算（峰值 ≤2000、保留 ≤100，最坏 2000 轮 × 每次 100 宽向量化，毫秒级）。排序键 `(-score, y, x)` 与 v1 完全一致。

预期：205ms → <10ms。不引入 scipy（cv2.dilate 已覆盖 maximum_filter 的用途，不新增依赖）。

### P2 模板解析缓存（速度，零行为变化）

在会话层加进程内 LRU（容量 ~32 项，键 = `(assets_root, logical, version_id)`）：

- 值缓存 `LoadedTemplate` 及派生数组（灰度图、HSV 三通道）；
- 清单中的 `version_id` 变化（资产原子切换）即失效，sha256 校验语义不变——缓存命中意味着"该版本的磁盘内容曾校验通过"，与 v1 的重读校验等强度（版本目录不可变是资产层既有不变量）；
- `TemplateStore` 本身不改，缓存放在 `adapter.py` 的 `_image_match` 路径上，viewer（`viewer/app.py:559`）独立使用时不受影响。

预期：每轮轮询省 ~1ms + 解码分配；主要是把 wait_for 高频轮询的常数项压平。

### P3 颜色验证升级：HSV 三通道相关性（准确率）

替换 `_color_matches` 的均值差门为 Airtest 风格的 HSV 相关性门：

1. 候选窗口与模板都 `np.clip(10, 245)` 后转 HSV；
2. H/S/V 三通道各自在窗口上做 TM_CCOEFF_NORMED，取最小值为颜色分；
3. 颜色分 ≥ `COLOR_CONFIDENCE_MIN`（初值 0.90，待正负样本组校准后固化）才通过；
4. 沿用角落置 0/255 技巧防平坦通道发散。

语义上仍执行 image.py 模块注释记录的 Q3 决定（同色轻微渲染差异接受、形状相同状态色不同拒绝），但判别力从"平均颜色接近"升级为"色相/饱和度/明度的空间分布一致"。灰度分仍是主分数（`MatchResult.confidence` 含义不变），颜色门是二值过滤，与 v1 结构相同。

需要同步：`COLOR_DIFF_MAX` 退役；正负样本组（现有 test_image_samples 扩展）上重校准 `COLOR_CONFIDENCE_MIN` 并把依据记录进 image.py 模块注释（沿用现有"校准初值"惯例）。边界效应：个别均值差 16–20 的灰阶边缘样本可能翻面，属预期修正，验收以样本组为准。

### P4 有界多尺度 + 采集位置先验（准确率，跨分辨率）

**P4a 有界多尺度（按元数据自动启用）**

- 触发条件：模板 meta 的 `source_width/height`（资产 schema v1 已有）与当前截图宽高不一致时启用；一致时走 v1 单尺度路径，行为零变化。
- 尺度窗口：期望比例 `s0 = 当前屏长边 / 采集屏长边`，扫描 `s ∈ [s0/1.3, s0×1.3]`；粗扫步长 0.05，最优尺度邻域细扫步长 0.01。
- 降本：粗扫与细扫都在"长边 ≤800px 的降采样图"上进行（Airtest src_max 同款）；模板缩放后任一边 <10px 则跳过该尺度；角落技巧防退化。
- 定位还原：取粗细扫最优尺度，回原尺寸截图在预测位置 ±(粗定位误差×2) 窗口内做一次全分辨率单尺度匹配，坐标与 confidence 都以全分辨率结果为准（Airtest `_get_confidence_from_matrix` 同款收尾，避免降采样分数偏低导致误拒）。
- 跨尺度重复命中由既有 NMS 自然去重。

**P4b 采集位置先验（可选，随 P4a 一起审查）**

- 资产 meta 升 schema v2：新增可选 `capture_center`（相对屏幕中心的归一化偏移，Airtest record_pos 同语义）；`TemplateStore.create` 增可选参数（内部 API 面，不是 adapter 面）；template studio 采集时自动写入。
- 匹配时若存在 `capture_center`：先在预测区域（边距 `max(模板宽×尺度, 150px)`）内搜索，未命中回退全区域——不改变"找不到就是找不到"的语义，只是搜索顺序。
- 收益：全屏搜索的匹配点数大幅减少（速度 + 远处相似图误匹配下降）。

**PRD 边界变更**：首版 PRD §2.2 明确排除"自动多尺度搜索"。P4 引入的是**分辨率先验的有界多尺度**（不是任意尺度/旋转搜索），需要批准后同步更新 PRD 该节表述。
