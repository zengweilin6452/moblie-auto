# Android 驱动、模板匹配与网页调试产品需求文档

**文档状态**：独立开发与交付需求基线；内网集成待验证  
**更新日期**：2026-10-24  
**产品定位**：独立实现 Android 驱动、模板图像定位及网页调试服务，交付可接入公司既有 pytest + browser-harness 框架的移动端能力包。  
**首版图像范围**：模板匹配；不包含 OCR。V2 起引擎支持基于模板采集分辨率元数据的有界多尺度适配与三段式颜色验证（docs/image-v2-plan.md，2026-10-24 审查批准）。  
**参考依据**：用户提供的《Mobile 驱动与图像识别接入说明》（文件名 `app自动化.md`，日期 2026-10-23，记录分支 `feat/ui-driver-adapter-layer`）。该说明作为接口参考，不要求接收者能够访问原始本机路径。

## 一、现状、目标与证据边界

### 1.1 已知现状

公司已有 Web 自动化框架位于内网电脑，源码无法带入当前开发环境。依据接入说明，内网已具备：

- `core/ui_driver.py` 中的 UiDriver、Locator、Target、ElementHandle、ListItemSchema。
- WebAdapter、平台 marker、`ui_driver` fixture，以及 `self.driver` / `self.browser` 双轨页面体系。
- MobileAdapter 骨架和尚未连接设备的 `mobile_device` fixture。
- 基于 OpenCV 模板匹配与 NMS 的共享 ImageMatcher。
- 已分类迁移的业务页面，其中 B 类页面仍需实现移动端业务分支。

上述属于**说明文档记载的状态**，本项目未读取内网源码，不能将其视为本地验证事实。说明中的接口摘要是兼容目标；完整类型、默认值和异常规则存在缺失，按第十二节管理。

### 1.2 本项目目标

1. 在不依赖内网 Web 框架的条件下，独立运行 Android 驱动和网页服务。
2. 提供语义定位与显式模板图像定位，完成操作、等待、截图和失败诊断。
3. 网页工具生成可用于既有 Target 契约的定位表达式和模板资产，减少人工转换。
4. 交付可安装、可测试、可移交的能力包、契约对应表和接入指南，方便内网装配。

本地完成表示具备交付条件；只有在内网真实框架中完成回归后，才能宣称集成验收通过。

### 1.3 本项目与内网的责任划分

| 领域 | 本项目交付 | 内网接入阶段负责 |
| :--- | :--- | :--- |
| 移动执行 | Android 执行核心、MobileAdapter 兼容入口、生命周期与错误处理 | 对接真实 UiDriver 和 `mobile_device` fixture |
| 图像定位 | 模板匹配实现、匹配器替换接口、共同行为样例和测试 | 对照已有 ImageMatcher，选择复用或替换并验证一致性 |
| 网页服务 | 设备画面、UI 树、定位符验证、模板制作与验证 | 在允许的环境中安装与使用 |

## 二、首版范围

### 2.1 支持边界

| 维度 | 首版定义 |
| :--- | :--- |
| 开发与运行主机 | Windows；固定 Python、主机和浏览器版本后验收 |
| 设备连接 | 单台 Android 真机，USB/ADB；串行运行 |
| 设备选择 | 支持既有 `MOBILE_DEVICE_SERIAL`；空值时仅在恰有一台已授权在线设备时自动发现，其他情况要求指定；不静默切换设备 |
| 原生定位 | RESOURCE_ID、TEXT、ACCESSIBILITY_ID、U2_SELECTOR、XPATH；语义与解析规则按契约对应表实现 |
| 图像定位 | 显式 IMAGE 模板匹配；可用于没有可用 UI 树节点的视觉目标，但不保证整个自绘应用的所有操作 |
| 网页入口 | 本机浏览器，服务仅监听回环地址 |
| 示例执行 | 独立 pytest Android 示例；驱动执行不要求网页服务运行 |
| 支持矩阵 | 仅声明通过验证的设备、Android、App、浏览器和依赖版本组合 |

优先使用语义定位。语义定位失败时不隐式改用图像；使用者通过 `Target(by=Locator.IMAGE, ...)` 明确选择图像定位。

### 2.2 不纳入首版

- OCR、文字图像读取、视觉大模型、通用目标检测、特征匹配及旋转搜索。
  （V2 修订:排除项中的"自动多尺度"调整为**采集分辨率元数据驱动的有界
  多尺度**——模板登记的 source 分辨率与当前截图不一致时自动启用,尺度

  仍排除。依据 docs/image-v2-plan.md 审查决定 1。)
- iOS、WebView 内部 DOM 自动化、通用游戏自动化和复杂手势。
- 多设备调度、pytest-xdist、设备农场、远程网页访问、无线 ADB。
  (P2 修订,2026-10-25:多设备调度与 pytest-xdist 已随设备池落地解除排除——
  见 .scratch/p2-platform/;远程网页访问与无线 ADB 仍排除。)
- 同一用例内 Web 与 Android 的跨端业务编排。
- 内网业务页面适配、WebAdapter 修改和已有框架重构。

## 三、独立架构与接入原则

### 3.1 模块职责

| 模块 | 职责与依赖边界 |
| :--- | :--- |
| Android 执行核心 | uiautomator2 会话、原生查询、输入、导航、截图；不导入内网项目或网页框架 |
| MobileAdapter 兼容层 | 对应已有异步 Port、Target 和句柄；隔离本地类型与内网真实类型的绑定 |
| 图像匹配模块 | 仅处理截图、模板、阈值和 ROI，返回匹配结果；不执行设备点击 |
| 设备会话协调 | 串行化设备调用，协调测试与调试进程的使用权 |
| 网页服务 | 调用同一定位与匹配能力，展示状态、制作模板、生成 Target 示例 |
| 示例与接入资料 | 独立 pytest 示例、契约测试、失败证据示例、内网接入步骤 |

本地用于开发的契约类型必须标记为“参考契约”，不能冒充内网实际类。集成时由薄兼容层绑定真实类型，禁止依赖两个不同类的 `isinstance` 恰好兼容。不得要求内网修改 Port 才能运行基础能力。

### 3.2 内网接入点

接入指南按说明中的路径描述目标，但不假设这些文件在当前仓库存在：

- `core/adapters/mobile_adapter.py`：装配或委托本项目实现。
- `testcase/conftest.py`：实现 `mobile_device` 连接和释放，与现有 `ui_driver` 配合。
- `config/config.py`：沿用 `MOBILE_DEVICE_SERIAL`、`MOBILE_APP_PACKAGE`、`MOBILE_APP_ACTIVITY`，新增配置采用明确默认值。
- `core/image_matcher.py`：选择已有引擎或本项目引擎，通过一致性测试后绑定。
- 依赖与报告配置：按内网策略安装依赖并挂接失败证据。

沿用 `platform("android")` 及已有 `web_only` 行为，不在本项目重写 Web 路由或假定未标记用例的真实默认行为。iOS 标记在原框架出现不表示本包支持 iOS。

## 四、异步 Port 与定位契约

### 4.1 方法清单与兼容状态

接入说明称“13 个方法”，但展示代码包含 **15 个异步方法及 `platform` 属性**。本项目以下表逐项跟踪，不以数字替代方法清单。签名取自说明；缺失语义在本地只能采用注明的暂定规则，内网验收前必须核对。

| 接口 | 兼容要求与首版职责 |
| :--- | :--- |
| `platform` | 返回 `"android"` |
| `goto(url, package=None, activity=None) -> None` | App 启动或 Deep Link；空值启动、链接格式与允许范围待核对，不能把任意字符串当 shell 命令；package/activity 显式覆盖配置(用于同一会话切换被启动 App)，缺省沿用配置 |
| `wait_for_load(timeout=30.0) -> None` | 仅承担 App 启动就绪：等待配置的启动就绪目标；业务页面就绪由页面对象显式 `wait_for` 表达；内网绑定时核对真实调用点语义，不以固定 sleep 或“进程存在”冒充加载完成 |
| `back() -> None` | Android 返回操作 |
| `click(target: Target \| ElementHandle) -> None` | 支持原生定位和 IMAGE；成功表示操作已发送，不代表业务已成功 |
| `input_text(target, text) -> None` | 原生可编辑节点输入；替换/追加规则待核对；IMAGE 边界见第五节 |
| `get_text(target: Target \| ElementHandle) -> str` | 返回原生节点文本；IMAGE 不提供 OCR |
| `get_attribute(target: Target \| ElementHandle, attr) -> str` | 原生属性读取；支持属性与缺失值规则待核对 |
| `wait_for(target, timeout=10.0) -> bool` | 保留 bool 返回及既有可取消循环结构；找到返回 True，未找到至超时返回 False 作为本地暂定规则；不新增 state 参数 |
| `is_visible(target) -> bool` | 查询当前是否存在符合可见性规则的目标；查询失败与未匹配必须区分 |
| `find_elements(target) -> list[ElementHandle]` | 支持原生与 IMAGE 查询；顺序及 index 行为见下节 |
| `extract_list(container, item_schema, max_items=None) -> list[dict]` | 原生列表结构化提取；依赖完整 ListItemSchema，缺失时不得以占位实现计作完成 |
| `screenshot() -> bytes` | 返回新采集且可解码的图像字节；本地固定编码并在接入时核对，不改变为元数据对象 |
| `press_key(key) -> None` | 有限 Android 按键映射；支持值与未知键错误待核对 |
| `scroll(direction="down", amount=300) -> None` | 保留签名；方向含义、距离单位与边界处理待核对，并用可观察结果验证 |
| `close() -> None` | 释放本适配器持有的资源；重复调用安全；不得默认关闭共享设备连接或终止外部 ADB 服务 |

新采集时间、尺寸、方向和快照 ID 由内部采集对象及证据层维护，不改变 `screenshot() -> bytes` 的 Port 返回类型。

所有方法均为异步入口。u2 同步调用通过线程桥接且同一设备串行执行。长等待使用短调用和可取消轮询；取消 `to_thread` 等待并不代表底层线程已经停止，未结束的调用不得与新操作并发或在释放锁后继续操作设备。实现须验证超时、取消及关闭时的在途请求处理。

### 4.2 Target 与匹配规则

沿用已有字段：`by`、`value`、`index`、`confidence`、`region`，不新增另一套 `strategy/selector` 公共定位格式。

- CSS 是 Web 专用，在 Android 返回明确的不支持错误。
- U2_SELECTOR 的 `value` 是字符串；序列化语法和支持字段须核对。禁止使用 `eval` 解析表达式。
- TEXT 的精确/包含匹配、XPath 支持范围及默认字段值需登记，不从摘要猜测为兼容事实。
- 网页工具生成同一 Target 解析器可接受的表达式；HTTP 传输可使用结构化数据，但不能创建第二套不同语义的定位协议。
- 本地暂定单目标操作：未指定 index 时要求唯一匹配；指定 index 时使用零起始序号并检查越界。查询返回顺序固定且写入契约测试。
- `find_elements` 与 `Target.index` 如何组合须核对；本地暂定无 index 返回全部，有 index 仅返回选定项，不能将此暂定规则宣称为内网现状。
- 图像结果默认按全截图坐标从上到下、从左到右排序；语义查询采用明确记录的驱动顺序。动态页面中的 index 不代表永久身份。

### 4.3 ElementHandle 与错误

`ElementHandle._raw` 对调用者保持不透明。说明中的 `(u2_selector_dict, instance_index)` 只足以描述部分原生查询；实现须区分原生选择器、XPath 和 IMAGE，支持 `click(handle)` 与 `get_text(handle)` 的可支持范围。

IMAGE 句柄保留模板引用、阈值、ROI、index、采集尺寸和会话归属等重新定位依据，不能只保存旧中心坐标。句柄不得跨设备或已关闭会话继续使用；过期原生句柄也不能默默指向任意新节点。

非法输入、无匹配、匹配歧义、设备不可用、不支持操作和取消需可区分。具体异常类与既有框架对齐；正常未找到的 bool 查询不应吞掉断连或模板损坏。可重试查询，不自动重放可能已生效的点击或输入。取消设发送阶段检查点：未进入发送阶段的操作取消后不得发送；已进入发送阶段的取消仅能报告结果未知，不承诺撤销。

Android 专属长按等能力可通过显式扩展提供，不新增 Port 方法，也不默认加入业务 App 的弹窗或菜单规则。

## 五、模板图像定位

### 5.1 引擎与复用边界

参考内网已有接口：`ImageMatcher.match(screenshot_bytes, template_path, confidence, region) -> list[ImageMatch]`。结果含 `x/y/width/height/confidence` 及 `center`。

本地采用 OpenCV 模板匹配与 NMS 去重，参考算法为 `TM_CCOEFF_NORMED`；灰度相关性仅用于候选定位，候选区域须再通过颜色差异验证，以区分形状相同、状态色不同的目标，颜色阈值由样本校准。引擎可替换；接入时允许选择内网已有实现或本地实现，但须使用共同样例校验阈值、ROI、NMS、排序与坐标含义，不默认两套实现结果一致。

ROI 输入按全截图像素 `(x, y, width, height)` 解释；匹配器对外统一返回**全截图坐标**，不能漏加或重复加 ROI 偏移。若内网实现采用局部坐标，由兼容层明确转换。阈值是相似度门槛，不是正确概率；默认值和有效范围随算法固定并写入配置与测试。

不强制优先使用 `d.match()`，也不静默在多个引擎间回退。其 API、版本和性能尚未核验，需要另行对照验证才可作为替代实现。

### 5.2 IMAGE 操作支持矩阵

| 操作 | 首版行为 |
| :--- | :--- |
| `click` | 使用新截图重新匹配，处理唯一性/index 后转换坐标并点击；尺寸、方向或会话失效则拒绝旧结果 |
| `is_visible` / `wait_for` | 按阈值和选择规则判断匹配；保持 bool 返回，非法模板与设备错误明确报错 |
| `find_elements` | 返回经过 NMS 和确定排序的匹配句柄 |
| `input_text` | 首版不支持 IMAGE 输入并明确报错；焦点验证与输入语义不足时不以全局键盘输入冒充成功 |
| `get_text` | 不支持 IMAGE 文本读取；OCR 不在首版范围 |
| `get_attribute` | 不伪造原生节点属性；匹配分数和边界通过调试结果展示 |
| `extract_list` | 首版不支持 IMAGE 容器或图像字段的结构化提取；原生列表提取单独按 schema 验证 |

“Port 全部有实现”不代表所有 Locator 与操作的组合均支持。上述不支持组合应有明确错误和测试，不以残留 `NotImplementedError` 作为正常交付行为。

### 5.3 模板资产与失配处理

- 模板存放于配置的资产根目录，Target 使用相对路径；不得依赖制作电脑的 Downloads 等绝对路径。
- 元数据记录模板标识与版本/内容摘要、原始分辨率、方向、显示缩放、主题、语言及适用说明；作为伴随资产，不改变 Target 字段。
- 首版按固定比例匹配；环境不一致时提示使用对应模板或重新制作，不自动缩放以掩盖不匹配。V2 修订（image-v2 P4a）：模板元数据登记的采集分辨率与当前截图不一致时，引擎按有界多尺度自动适配（期望比例 ±1.3 倍），分辨率一致时行为与固定比例完全相同；方向、主题、语言变化仍要求更换模板。
- 模板不存在、损坏、尺寸大于截图/ROI、ROI 越界、低纹理或近纯色模板，以及非有限匹配分数均需显式处理，不能误判为可信匹配。
- NMS 去重阈值和排序规则固定可测；多目标且未指定 index 的点击不自动取最高分目标。
- 匹配到点击之间存在页面变化窗口，不能承诺原子操作；使用新截图、限制结果有效期，并由用例验证操作后的业务状态。有效期阈值在真机基线上确定。

## 六、网页调试流程

### 6.1 模式与设备使用权

| 模式 | 功能 | 版本 |
| :--- | :--- | :--- |
| 查看 | 设备画面、UI 树、属性、连接状态 | P0 |
| 原生拾取 | 冻结画面与树、双向高亮、候选生成及当前匹配验证 | P0 |
| 图像制作与验证 | 框选模板、保存资产、设置 ROI/阈值、重新匹配、高亮、生成 Target | P0 |
| 直接控制 | 在画面上发送点击和滑动 | P1，显式启用 |

P0 网页拾取与框选不会向设备发送操作；P0 驱动本身已支持 IMAGE 点击，两者不混淆。

设备使用权跨进程协调。pytest 或独立驱动执行期间，网页只显示已有快照，禁止新的主动采集和设备操作。P1 控制复用同一占用机制。异常退出须能恢复锁，但不能抢占仍在运行或仍有在途调用的会话。外部未接入本工具的操作不在锁的保证范围内。

### 6.2 首次使用与原生定位

1. 按固定依赖安装工具、连接并授权设备，执行环境检查。
2. 检查设备选择、截图、UI 树及匹配器可用性，分别报告能力状态。环境检查仅执行无副作用探测；可能触发设备端组件初始化或写入的检查作为单独的显式步骤执行。
3. 运行独立 Android 冒烟用例，然后打开网页调试页。
4. 冻结截图和 UI 树，拾取节点，生成 Target 候选。
5. 在当前设备状态重新查询，显示匹配数量和高亮，复制表达式用于示例用例。

截图与 UI 树分别标记采集时间，并关联快照 ID、尺寸、方向和设备。两者并非原子采集；采集间隔超限、页面变化或旋转时要求刷新。浏览器缩放和留白必须正确映射到设备截图坐标。重叠节点允许用户选择，不能静默选中任意节点。

### 6.3 图像定位制作闭环

1. 获取并冻结设备原始截图，用户框选目标生成模板预览。
2. 用户指定资产名称，保存模板及元数据；默认不覆盖同名文件，覆盖须明确确认。
3. 用户设置可选搜索区域和匹配阈值。
4. 对当前新截图进行验证，展示匹配数量、分数和边界框。
5. 多目标时展示稳定序号，用户确认是否使用 index；零匹配不能显示为通过。
6. 生成包含 `Locator.IMAGE`、相对模板路径、阈值、ROI 和可选 index 的 Target 表达式。
7. 用户在独立示例中执行并验证后置业务状态，所用模板与网页产物一致。

模板匹配始终使用原始截图像素，不使用浏览器压缩后的预览图。UI 树不可用时禁用原生拾取，但截图可用则保留模板制作和匹配能力。分辨率或方向变化后，原 ROI 和索引必须重新验证。模板编辑期间的冻结快照保持固定引用，不受服务端实时快照数量上限驱逐；退出编辑或超时后显式释放。

## 七、运行、证据与数据处理

### 7.1 异常与资源管理

设备未授权、离线、错误序列号、无设备或多设备未选择时均给出明确错误，不静默选取其他设备。断连后停止无效采集；恢复连接不自动续跑已失败用例。底层设备调用无法结束时，故障影响范围为宿主进程：会话拒绝后续设备操作，失败取证只保存已有材料并注明无法采集，由操作者确认设备与 App 状态后重启宿主进程恢复；不承诺不重启进程的在线恢复。

示例 session 级设备 fixture 与 function 级 Adapter 必须区分资源所有权：用例结束只释放本次占用和包装器，session 结束才释放共享会话。异常中断、初始化失败、取消及重复关闭均纳入验证，不默认退出业务 App 或重启外部 ADB。

执行不依赖调试服务。P0 提供基础资源回收；P1 引入 scrcpy 时同步交付其启停、异常回收和回退，不拖到多设备阶段。

### 7.2 失败证据

本地提供独立证据采集与示例失败钩子，内网再挂接真实报告。证据至少包括：

- 用例、操作、失败阶段、时间、设备与 App 基线、原始异常。
- 在可访问时采集新截图与 UI 树，分别记录采集时间和采集失败原因。
- IMAGE 失败附模板标识/内容摘要、实际匹配截图、ROI、阈值、引擎版本、候选边界和分数；未产生候选时记录空结果及原因。
- 区分“操作时使用的截图”和“失败后新采集的截图”，不将后者冒充前者。

采集在释放设备之前进行并设置超时，不覆盖原始错误。截图元数据保存在证据对象中，不改变 Port。未连接设备的初始化失败也应留下错误记录，不能假装已有现场截图。证据写入本地运行产物目录并登记运行清单；网页调试服务只读取清单登记的条目，不提供任意文件访问。设备会话已故障挂起时，取证不得再调用设备采集，只保存已有材料并记录无法采集的原因。

### 7.3 本机与内网约束

- 网页服务仅监听回环地址，限制请求来源；不提供任意命令执行。
- 模板读取与保存限制于配置的资产目录，拒绝路径穿越和未经确认的覆盖。
- 运行时不依赖外网模型、云识别、CDN 或在线许可证校验；前端资源随交付物提供。
- 截图、模板、树和证据默认保存在本地，不上传；使用测试账号和测试数据，日志不输出凭据。
- 不自动删除历史证据或模板；保留期限与清理由团队按授权规则管理。
- Python 依赖、ADB、u2 设备端组件及初始化可能需要的文件，均列出来源、版本、许可证和预置方法；离线部署须单独演练，不能仅因运行无外网请求就宣称可离线安装。

### 8.2 P1：体验优化

**实施结果（2026-10-24，本地验收通过；实测记录见 docs/validation.md P1 章节）**：采用 wetest-scrcpy 客户端 + 服务端解码 JPEG over 既有 WS（未做浏览器端 h264 解码，消除目标浏览器解码差异风险）；预览 ≥8fps、杀 server ≤3s 回退并自动恢复；驱动截图双通道（`screenshot_source=auto`，CAPTURE 全分辨率，匹配一致性基线通过，时延中位 u2 141ms vs scrcpy 62ms）；网页直接控制显式启用（tap/swipe/back/home/亮屏，租约门控）；失败取证优先视频帧并经 pytest 钩子附加报告。wetest-scrcpy 许可证未标注，stream extra 为条件交付（不装自动回退 u2，P0 能力不受影响）。

**上游迁移修订（2026-10-25，feat/scrcpy-upstream 分支，见 §8.5）**：P1 的 wetest 实现为通道后端之一（`stream_backend="wetest"`）；默认通道已切换为上游官方 server v5.0.1（Android 16 QPR2+/17 兼容）。上段 "CAPTURE 全分辨率" 仅适用于 wetest 后端——上游后端无 CAPTURE 消息，取证截图分辨率=流分辨率（`max_size` 默认 1080），语义变更详见 §8.5。

### 8.5 P2 修订：scrcpy 上游迁移（2026-10-25）

**背景**：Android 16 QPR2+ 给 `IDisplayWindowListener` 新增 binder 回调，wetest 内嵌 server（基于 scrcpy 1.2.4 协议）触发 `AbstractMethodError` 起流即崩（上游 issue #6362 逐字复现，真机 84cb2c4e/Android 17 实证）；wetest-scrcpy 0.4.0 为 PyPI 最新且无修复、server 源码不公开、许可证未标注。

**方案**：自研薄客户端对接上游官方 server v5.0.1（Apache-2.0），双通道可切换——`stream_backend = upstream（默认）| wetest`，两实现同接口，supervisor/降级/自愈语义不变。协议对照 v5.0.1 源码逐项核实（spec 见 `.scratch/scrcpy-upstream/`，本地保留）。

**语义变更（随本修订生效）**：
- `capture_png`（驱动取证截图）：上游后端返回**当前解码帧**，分辨率=流分辨率（`max_size` 默认 1080；wetest 后端保持设备原生分辨率的 CAPTURE）。需要全分辨率取证时用 `screenshot_source="u2"` 或显式切回 wetest 后端。失败证据链路不受影响（本就优先视频帧 + u2 回退，两类后端同形）。
- 驱动截图双通道策略（`screenshot_source`）与通道后端（`stream_backend`）正交：前者选"截图来自哪条通道"，后者选"通道用什么 server 协议"。

**验收**（双真机，2026-10-25）：Android 17（84cb2c4e）启动 1.0s、60s 存活 ~19.9fps、控制注入生效、stop 零残留；Android 14（749622c9）同项回归通过；双机 viewer 并发出流；残留自愈双前缀（wetest `ma-` comm + upstream `scid=` cmdline）。上游 server 在客户端断开时自退出（宿主异常终止不产生残留，硬杀实验与通道实验互证）。

**遗留**：wetest 通道删除工单（待内网设备矩阵验证后执行，删除时同步移除 libjpeg-turbo 依赖与 CAPTURE 相关表述）。

### 11.2 内网集成验收

- 使用真实 UiDriver、Target、ElementHandle、ListItemSchema 完成契约测试，核对默认值和异常语义。
- 验证 session 级 `mobile_device` 与 function 级 Adapter 的生命周期，不提前关闭共享设备。
- 验证既有 ImageMatcher 与本地样例的 ROI、阈值、NMS、排序和句柄调用一致性。
- 在同一环境和固定用例集比较接入前后 Web 收集数、跳过规则与结果，无新增回归；记录时长变化并定位明显退化。
- 完成实际业务页面 B 类分支和代表性移动业务流程，核对 A 类页面对 Port 的真实依赖。
- 验证报告附件、配置加载、依赖安装和内网运行约束。

本地契约替身、模拟设备或网页截图不能代替以上验收。未取得内网结果时只报告“本地验收通过，内网集成待验证”。

### 11.3 用户价值指标

在工具可用后评估，不以访问不到内网的指标阻塞本地开发：

- 首次接入时间：从具备安装前提到示例首次通过，分开记录安装、授权、配置耗时。
- 定位效率：至少 10 个代表性目标，分开统计原生和 IMAGE，从开始定位到验证通过的中位数、P90、失败次数；初始目标中位数不超过 2 分钟。
- 编写与调试收益：与现有方式完成相同任务，初始目标中位耗时下降 20%，完成率不下降；无基线则先测基线。
- 实际采用：内网试用时记录适用任务中的使用和弃用原因，不用页面打开次数代替收益。

上述数值为验证目标，不是已测结果。性能记录设备、分辨率、连接、算法与浏览器版本，区分采集、匹配、传输、显示和输入响应耗时。
