# 05: 失败证据与运行清单

**What to build:** 用例失败后现场可复盘：自动保存新截图、UI 树、异常与各自采集时间，区分操作时画面与事后取证画面；证据写入产物目录并登记运行清单（后续网页读取的唯一入口）；设备会话故障挂起时降级留证（spec 用户故事 21、22 部分、23）。

**Blocked by:** 03 原生定位与操作补全

**Status:** resolved

- [x] 真机失败用例产出证据：截图、UI 树、异常类型、时间、设备与 App 基线，各自带采集时间与失败原因
- [x] 操作时使用的画面与失败后新采集的画面分开保存并标注，不互相冒充
- [x] 证据写入配置的产物目录并登记运行清单；清单是唯一读取入口
- [x] 初始化失败与清理失败保留原始测试错误，不被取证错误覆盖
- [x] 会话故障时只保存已有材料并记录"无法采集"原因
- [x] 取证有超时，失败用例不因取证挂起；日志与证据不含输入文本与凭据


## Answer

交付(本工单提交):

- `evidence.py`(新文件):`collect_failure_evidence`——操作时画面(调用方在操作中采集,单独命名保存)与失败后新采集的画面/UI 树分开保存,各自带 UTC 采集时间;失败信息记录类型与消息;设备基线(序列号/App 包名/屏幕尺寸);FAULTED 会话不再调用设备线程只保存已有材料并留因;取证提交与等待均有界(默认 5 秒,超时放弃不挂起用例);`read_manifest`/`read_evidence_file`——运行清单(run-manifest.jsonl)是证据读取唯一入口,未登记名称拒绝、非法证据标识拒绝、损坏行跳过。
- `tests/device/conftest.py`:makereport 钩子 + evidence 记录器夹具;用例失败(含 xfail 的 wasxfail 报告)在会话关闭前收集证据;取证异常被吞并打印,原始测试错误不受影响。
- `tests/device/test_failure_evidence.py`:故意失败(strict xfail)→ 证据产出 → 清单断言的闭环。
- `tests/unit/test_evidence.py`:7 项覆盖读写、故障降级、挂起超时、提交拒绝、无输入文本、清单抗损坏。

验证:ruff 0 问题;单元 133 项通过;真机 6 项(xfail 1 + 通过 5)通过,证据落盘于 tests/device/artifacts/。

决定与说明:
