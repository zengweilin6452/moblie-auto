# mobile-auto：Android 移动能力包 spec

**Status:** open

**来源**：本 spec 由 2026-10-24 的需求评审、PRD、开发方案（同目录 `plan.md`）与两轮复审（Q1–Q4 已确认）合成，术语见根目录 `GLOSSARY.md`。测试接缝划分已经用户确认。

## Problem Statement

测试团队已有基于 pytest 的 Web 自动化资产，但 Android 端缺失：移动用例无法进入同一套流水线；定位元素依赖与执行框架割裂的独立工具，看完还要手工翻译成用例代码；用例失败后缺少能对应现场的截图、UI 树与异常记录。内网虽有统一驱动契约与适配层骨架，但移动端执行核心、图像定位和调试工具尚未实现，且内网代码不可在当前开发环境访问，能力必须独立开发、再经绑定层接入。

## Solution

交付一个独立的 Android 移动能力包：Python 驱动实现统一驱动的全部异步方法（原生语义定位 + 显式模板图像定位），加上一个仅监听本机的网页调试服务，打通"看画面 → 拾取元素 / 制作模板 → 验证定位 → 生成 Target → 执行 → 查看失败证据"的闭环。内网通过薄绑定层接入，不修改内网 Port。移动用例获得与 Web 用例一致的编写体验；不开发 Android 测试 App，不做 OCR。

## User Stories

### 连接与运行环境

1. 作为移动测试工程师，我希望执行一条命令即可检查依赖版本、ADB 可见性与设备授权状态，以便在写用例前确认环境可用。
2. 作为移动测试工程师，我希望通过配置指定设备序列号，并在无设备、多设备未选、未授权或序列号错误时得到明确错误，以便避免误操作错误的设备。
3. 作为移动测试工程师，我希望只运行旧 Web 用例时不要求安装任何移动端依赖或启动任何移动服务，以便现有流水线完全不受影响。

### 原生定位与操作

4. 作为移动测试工程师，我希望用资源 ID、文本、可访问性描述、u2 选择器和 XPath 五种定位描述定位原生控件，以便优先选用最稳定的语义定位方式。
5. 作为移动测试工程师，我希望点击与输入前自动等待目标可见且唯一（或显式指定序号），以便不在用例里手写等待与重试。
6. 作为移动测试工程师，我希望输入文本是"清空并替换"的确定语义，并对不可编辑目标明确报错，以便用例行为可预期。
7. 作为移动测试工程师，我希望读取文本与属性时区分"已知但为空"与"未知属性"，以便写出可靠的断言。
8. 作为移动测试工程师，我希望返回键、按键与滚动有确定的方向与距离语义，以便跨用例一致地导航。
9. 作为移动测试工程师，我希望等待方法返回布尔且可取消，"未找到"与"设备错误"分开报告，以便等待失败可诊断。
10. 作为移动测试工程师，我希望 App 启动与 Deep Link 受配置白名单约束、经参数化调用执行，以便驱动不被当作任意 shell 入口。
11. 作为移动测试工程师，我希望 App 启动就绪由显式配置的启动就绪目标表达，业务页面就绪由我自己的等待表达，以便就绪语义不被全局配置绑架。

### 查询句柄

12. 作为移动测试工程师，我希望一次查询返回的句柄可直接用于点击与取文本，并在页面变化或会话失效时报"句柄过期"而非指向别的节点，以免误操作。

### 图像定位

13. 作为移动测试工程师，我希望对 UI 树无法覆盖的视觉目标用模板图像定位并点击，以便自绘界面也能自动化。
14. 作为移动测试工程师，我希望模板匹配区分"形状相同、颜色不同"的状态，以便启用/禁用、成功/失败类状态不会被误点。
15. 作为移动测试工程师，我希望可限定搜索区域并得到全图坐标的匹配结果与分数，以便大画面下匹配又快又稳。
16. 作为移动测试工程师，我希望匹配无结果是明确的查询结果（count=0）而不是报错或静默通过，以便区分"目标不在"与"工具坏了"。
17. 作为移动测试工程师，我希望图像句柄重新使用时校验模板版本、会话与位置一致性，以免页面重排后点错列表项。

### 模板资产

18. 作为移动测试工程师，我希望在网页上框选画面直接生成模板并自动记录分辨率、方向、来源等元数据，以便不用截图工具手工裁剪。
19. 作为移动测试工程师，我希望模板按版本不可变存储、更新需确认旧版本并在锁内校验摘要，以便团队共享的模板不被静默覆盖。
20. 作为移动测试工程师，我希望模板以资产根目录内的相对路径引用并可随包迁移，以便换机器后用例不失效。

### 失败证据

21. 作为移动测试工程师，我希望用例失败时自动保存新截图、UI 树、异常与各自采集时间，并区分"操作时画面"与"事后取证画面"，以便复盘时还原现场。
22. 作为移动测试工程师，我希望图像定位失败时证据包含模板、搜索区域、阈值、候选分数与匹配截图，以便解释"为什么没找到"或"为什么点错"。
23. 作为移动测试工程师，我希望设备线程挂起时取证只保存已有材料并注明无法采集，以便故障时也能留下可诊断的记录。

### 并发与设备占用

24. 作为移动测试工程师，我希望 pytest 运行期间网页停止主动采集，测试与调试经同一把跨进程设备租约协调，以便调试不引入随机失败。
25. 作为移动测试工程师，我希望取消一个等待不会再发送新的设备操作，已进入发送阶段的操作如实报告结果未知，以便用例超时不引发重复业务动作。
26. 作为移动测试工程师，我希望会话故障后明确拒绝后续设备操作并提示重启宿主进程，以便故障不被静默吞掉后继续误操作。

### 网页调试

27. 作为移动测试工程师，我希望在浏览器里实时看到设备画面与 UI 树并分别标注采集时间，以便不安装桌面工具即可查看设备。
28. 作为移动测试工程师，我希望冻结一组画面与树后双向拾取（点画面高亮树节点、点树节点画边界框），以便快速选对控件。
29. 作为移动测试工程师，我希望在网页上验证任意定位描述（重新查询、显示匹配数量与高亮）后，复制可直接粘贴进用例的 Target 表达式，以便消除"工具里看到的"与"用例里用的"之间的手工翻译。
30. 作为移动测试工程师，我希望编辑模板期间冻结快照不被驱逐，以便框选到一半不会丢画面。
31. 作为移动测试工程师，我希望设备忙或离线时网页如实显示占用与连接状态，以便知道该等待还是该修环境。

### 工程化与内网接入

32. 作为内网框架维护者，我希望拿到绑定骨架、契约测试模板与契约版本记录，以便把本包接到真实 Port 与 fixture 而不修改内网接口。
33. 作为内网框架维护者，我希望本地图像引擎能与内网 ImageMatcher 用同一组样例对照结果，以便据证据决定复用还是替换。
34. 作为内网框架维护者，我希望接入清单写明依赖版本、设备端组件与 OpenCV 共存验证步骤，以便内网离线安装可执行。
35. 作为测试工具开发者，我希望匹配器可替换、参考契约与执行核心隔离，以便内网差异不污染独立核心。
36. 作为团队负责人，我希望真机证据分三类（演示 App 操作、截图样本算法、模拟设备并发）分别记录，以便验收时不被替代性证据误导。

## Implementation Decisions

- **形态**：独立 Python 包 + 本机 FastAPI 网页服务。pytest 直接调用 Python 驱动，不经 HTTP；网页与驱动共享同一设备会话、定位与匹配实现；依赖单向（网页依赖核心，核心不依赖网页框架，不导入内网项目）。
- **参考契约与绑定层**：本地定义与内网统一驱动形状一致的参考契约（15 个异步方法 + platform 属性：goto、wait_for_load、back、click、input_text、get_text、get_attribute、wait_for、is_visible、find_elements、extract_list、screenshot、press_key、scroll、close）。绑定层部署在内网仓库，负责真实 Target 枚举归一化、句柄包装与异常映射；不依赖两个同名类的 isinstance 巧合，不要求内网改 Port。
- **异步桥接**：同步 uiautomator2 调用线程化，每设备单 worker 串行执行；长等待拆为短轮询，轮询间隙允许取消；不在跨事件循环场景复用绑定单个 loop 的 asyncio 锁（session 级 fixture 与 function 级 loop 组合有专项测试）。
- **取消语义**：每个操作携带取消标记，进入设备发送阶段前在锁内做最后一次取消检查；"匹配完成后、点击发送前取消"不得发出点击（必测路径）；已进入发送阶段的操作被取消时结果记为 unknown，不自动重放。
- **会话状态机**：NEW → READY → LEASED → DRAINING → READY，关闭进入 CLOSED，无法确认在途操作结果进入 FAULTED。挂起故障影响范围为宿主进程（决定 Q1）：FAULTED 后拒绝后续设备操作、取证不再调用设备，由操作者确认设备与 App 状态后重启进程恢复；close 超时与进程可退出是两个概念，不得混用。
- **设备租约**：跨进程文件区域锁（Windows），锁文件统一目录、按设备序列号摘要命名；锁随 OS 句柄生命周期释放，不靠删除文件或 PID 过期偷锁，不提供强制抢占；保证范围为同一 Windows 登录用户。
- **启动就绪**（决定 Q2）：`wait_for_load` 仅等待配置的启动就绪目标（launch_ready_target）；业务页面就绪由调用方 `wait_for` 表达；内网绑定时核对真实调用点语义。
- **图像匹配**（决定 Q3）：灰度 TM_CCOEFF_NORMED 做候选定位，候选区域再经颜色差异验证（同色轻微渲染差异接受、形状相同状态色不同拒绝）；NMS 去重、(y,x) 稳定排序、结果统一全图坐标；低纹理模板、非有限分数、候选溢出均显式拒绝。灰度阈值、NMS IoU、句柄 IoU、颜色阈值与坐标容差均为样本校准初值，调整须记录依据。
- **IMAGE 操作矩阵**：click、is_visible、wait_for、find_elements 支持 IMAGE；input_text、get_text、get_attribute、extract_list 对 IMAGE 明确报不支持，不以残留未实现错误交付。
- **模板资产**：模板逻辑名 + 不可变模板版本 + 清单原子切换当前版本；图片与元数据成对完整写入后清单才切换，不存在"新图片配旧摘要"中间态；更新在资产级锁内校验旧摘要；引用为资产根内相对路径，拒绝路径穿越；元数据记录采集分辨率、方向、App 与时间。
- **句柄**：原生句柄保留定位描述与节点关键属性，IMAGE 句柄保留模板摘要、搜索区域、序号、原边界、屏幕尺寸与方向、会话代；重用前重新校验，身份无法确认时报句柄过期，不重定向到新节点。
- **失败证据**：证据写入本地产物目录并登记运行清单，网页仅读清单登记项；区分操作时画面与事后取证画面；设备会话故障挂起时只保存已有材料并记录无法采集原因；不记录输入文本与凭据。
- **网页服务**：仅监听回环地址，只留端口覆盖选项；lifespan 管理会话；HTTP/WS v1 接口覆盖状态、快照、UI 树、定位验证、模板创建/更新/列举/验证、证据读取与预览推送；校验请求来源；资源上限（实时快照份数/总数据量/有效期、单张像素与文件大小、匹配作业并发 1、预览 1fps 与最多 2 客户端）；冻结快照在编辑期间固定引用不受驱逐。
- **CLI**：单一入口两个子命令——doctor 仅做无副作用检查（依赖版本、ADB 可见性、已授权设备在线），设备端组件初始化是独立显式步骤；serve 启动网页服务。
- **配置**：优先级为显式构造参数 > 三个沿用内网名称的环境变量（设备序列号、App 包名、启动 Activity）> TOML > 默认值；不新增环境变量；Deep Link scheme 白名单默认为空。
- **依赖**：核心为 uiautomator2 与 Pillow；图像能力为 OpenCV headless extra（内网接入不得覆盖既有 OpenCV 发行包，组合单独验证）；网页能力为 FastAPI/Uvicorn extra；前端为随包分发的原生 HTML/CSS/JS，不引入 Node 构建与前端框架；目标 Python 3.12，发布版本以锁定清单加实测为准。
- **测试载体**（决定 Q4）：不自建 Android 测试 App；真机操作用固定来源、版本与摘要的现成演示 App，图像算法用固定截图样本，取消与竞态用模拟设备；三类证据分别记录、互不替代。
- **extract_list**：在真实 ListItemSchema 与行为样例到位前不实现、不伪造兼容 schema（内网交接门槛）。

## Testing Decisions

- **好测试的标准**：只测接缝的外部行为（输入 → 可观察输出与状态转换），不测实现细节（线程结构、NMS 中间数组、锁文件格式、内部方法调用序列）。
- **四个已确认接缝**：
  1. MobileAdapter 异步公共接口（主接缝）：注入伪造设备后端驱动全部 15 个方法，覆盖定位规则、等待语义、取消检查点、错误分类、句柄校验与 IMAGE 支持矩阵。
  2. ImageMatcher 纯函数：（截图、模板、阈值、搜索区域）→ 匹配结果列表；固定截图样本验收坐标、排序、NMS 与颜色验证（同色渲染差异、同形异色两组样本各自验收）；可脱离驱动独立运行，供内网引擎对照。
  3. DeviceSession 公共表面：模拟设备验证取消窗口、FAULTED 拒绝与取证降级、close 排空、重复关闭；两进程文件锁争用为集成测试。
  4. 网页 HTTP/WS API：TestClient + 注入伪造会话，覆盖快照、模板版本与摘要冲突、定位验证、来源检查、错误码映射与设备忙/离线状态。
- **真机层**：是接缝 1 在真实后端上的验证层（演示 App），按配置文件门控；无设备时不运行、不计为通过；演示 App 无法覆盖的场景明确列为未验证。
- **三类证据互不替代**：真机操作（演示 App）、图像算法（截图样本）、取消与竞态（模拟设备）；以样本或模拟结果冒充真机验证不构成通过。
- **可靠性口径**：固定场景真机重复至少 30 次逐次归因，零未解决工具原因失败才通过；小样本不外推长期失败率。
- **Prior art**：无（绿地仓库，本 spec 的测试即项目首批测试；测试结构与命名由本 spec 与开发方案确立）。

## Out of Scope

- OCR、文字图像读取、视觉大模型、通用目标检测、特征匹配、自动多尺度/旋转搜索。
- IMAGE 输入（input_text）、IMAGE 文本/属性提取、IMAGE 容器列表提取。
- iOS、WebView 内部 DOM 自动化、多设备调度与设备池、pytest-xdist 并行、远程网页访问、无线 ADB、跨用户设备共享。
- 同一用例内 Web 与 Android 跨端编排；WebAdapter 与内网业务页面（含 BYD B 类分支）的修改。
- extract_list 的完整内网绑定（待真实 ListItemSchema 与行为样例）；内网 ImageMatcher 的复用决策（对照后另行决定）。
- scrcpy 视频加速与网页直接控制（属 P1，另行立项）。
- 自建 Android 测试 App。

## Further Notes

- 内网交接门槛与责任分工：真实 Port 默认值与异常语义、ListItemSchema、引擎对照结果、内网安装策略、业务页面回归均由内网方提供证据；未提供前只能声明"本地验收通过，内网集成待验证"。
- 工期估算 24–35 个开发工作日；演示 App 覆盖度确认前仅为粗估，四个阶段各自独立可用、可单独回退。
